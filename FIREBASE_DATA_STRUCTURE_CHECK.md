# Проверка структуры данных Firebase для SafeOrbit

## Цель

Убедиться, что структура данных в Firebase соответствует новым безопасным правилам.

## Текущая структура (ожидаемая)

```
{
  "servers": {
    "$serverId": {
      "ownerUid": "string",  // UID владельца сервера
      "pairing": {
        "tokenHash": "string",  // SHA-256 хеш одноразового токена
        "expiresAt": "number",  // timestamp истечения токена
        "consumed": "boolean"   // флаг использования токена
      },
      "location": {
        // данные местоположения
      },
      "app_notifications": {
        "$notificationId": {
          "enc_pkg": "string",      // зашифрованный package name
          "enc_label": "string",    // зашифрованный app label
          "enc_title": "string",    // зашифрованный заголовок
          "enc_text": "string",     // зашифрованный текст
          "post_time": "number"     // timestamp уведомления
        }
      }
    }
  },
  "server_commands": {
    "$serverId": {
      "$commandId": {
        "type": "string",           // "request_location_update" или "update_settings"
        "created_at": "number",     // timestamp создания команды
        "request_location_update": "boolean",  // для типа "request_location_update"
        "update_settings": {
          "active_interval": "number",        // интервал активности
          "inactivity_timeout": "number"      // таймаут неактивности
        }
      }
    }
  },
  "clients": {
    "$clientId": {
      "linked_servers": {
        "$serverId": "true"  // флаг связи клиента с сервером
      }
    }
  }
}
```

## Проверка соответствия новым правилам

### 1. Права доступа

- [ ] Владелец сервера может читать/писать все данные сервера
- [ ] Связанный клиент может читать местоположение и уведомления сервера
- [ ] Связанный клиент может отправлять команды серверу
- [ ] Посторонние пользователи не имеют доступа к чужим данным

### 2. Pairing система

- [ ] Pairing токены хранятся только в виде хеша (tokenHash)
- [ ] После использования токена флаг consumed устанавливается в true
- [ ] Нельзя изменить consumed обратно на false
- [ ] Токены имеют ограниченное время жизни (expiresAt)

### 3. Команды сервера

- [ ] Команды не содержат секретных данных (токенов, кодов)
- [ ] Структура команд валидируется на соответствие допустимым типам
- [ ] Интервалы команд проверяются на допустимые диапазоны

### 4. Уведомления

- [ ] Уведомления хранятся в зашифрованном виде
- [ ] Структура уведомлений валидируется на наличие всех необходимых полей
- [ ] Только владелец сервера может записывать уведомления

## Тестирование

Для проверки можно использовать Firebase CLI:

```bash
# Установка Firebase CLI
npm install -g firebase-tools

# Авторизация
firebase login

# Выбор проекта
firebase use <project-id>

# Получение данных
firebase database:get --path / -o backup.json
```

Затем проверить структуру данных в полученном файле на соответствие ожидаемой структуре.
