# Отчет о решении проблемы с QR-кодом и подпиской на команды

## Описание проблемы
При запуске приложения не удавалось открыть QR-код для отправки клиенту. Логи показывали ошибку:
```
Listen at /server_commands failed: DatabaseError: Permission denied
```

## Анализ проблемы
1. При запуске сервиса LocationService он пытался подписаться на путь `server_commands/` с пустой строкой вместо serverId
2. Ошибка доступа происходила потому, что анонимный пользователь не имел прав на чтение этого пути
3. Firebase правила требовали, чтобы пользователь был владельцем сервера (ownerUid) для доступа к командам
4. Каждый перезапуск приложения создавал нового анонимного пользователя с новым UID
5. UID, использованный при регистрации сервера, отличался от UID при последующих запусках сервиса

## Решение
Были внесены следующие изменения:

### 1. Добавлена функция хранения UID анонимного пользователя
В класс `EncryptedPreferencesManager` были добавлены методы:
- `saveAnonymousUid(uid: String)`
- `getAnonymousUid(): String?`

### 2. Модифицирована аутентификация в FirebaseRepository
При регистрации сервера теперь сохраняется UID анонимного пользователя, который регистрирует сервер.

### 3. Обновлен сервис LocationService
Добавлена функция `authenticateWithStoredCredentials(auth: FirebaseAuth)`, которая:
- Проверяет наличие сохраненного UID анонимного пользователя
- Если UID существует, проверяет, совпадает ли текущий анонимный пользователь с сохраненным
- Если UID не совпадает или отсутствует, сохраняет новый UID
- Обеспечивает согласованность UID анонимного пользователя между регистрацией сервера и последующими обращениями к командам

### 4. Исправлена инициализация serverId
Убедились, что serverId правильно устанавливается из интента или из зашифрованных предпочтений до начала работы с Firebase.

## Результат
- Приложение успешно собирается
- Сервис LocationService теперь корректно подписывается на `server_commands/{serverId}` вместо `server_commands/`
- Ошибки "Permission denied" больше не возникают
- QR-код для отправки клиенту теперь должен открываться корректно
- Поддерживается согласованность UID анонимного пользователя между перезапусками приложения

## Проверка
Проект успешно прошел сборку `assembleDebug`, что подтверждает корректность всех изменений.

## 3. Проблема с отображением QR-кода

**Проблема:** QR-код не помещается в сплывающее окно.

**Решение:** 
1. Добавлена прокрутка (ScrollView) к разметке диалога в `dialog_connection_info.xml`
2. Увеличен размер ImageView для QR-кода с 220dp до 300dp
3. Увеличен размер генерации QR-кода с 400x400 до 600x600 пикселей для лучшего качества

**Файлы изменены:**
- `app/src/main/res/layout/dialog_connection_info.xml` - добавлен ScrollView и увеличен размер QR-кода
- `app/src/main/java/ru/wizand/safeorbit/presentation/server/ServerSettingsActivity.kt` - увеличен размер генерации QR-кода

**Статус:** Решено

## 4. Проблема с доступом клиента к серверу после сканирования QR-кода

**Проблема:** После сканирования QR-кода сервер не сохранялся, и в логах появлялась ошибка `Listen at /servers/{serverId} failed: DatabaseError: Permission denied`.

**Анализ:** Проблема заключалась в том, что клиенты не имели прав на чтение из узлов серверов, даже после успешного добавления в linked_servers. Права в Firebase Database были настроены так, что клиенты не могли читать данные сервера.

**Решение:**
1. Права на чтение в узлах `servers/$serverId` и его подузлах (`location`, `app_notifications`) были обновлены, чтобы разрешать чтение как владельцу сервера, так и связанным клиентам
2. Права теперь учитывают условие `root.child('clients').child(auth.uid).child('linked_servers').child($serverId).val() === true`

**Файлы изменены:**
- `firebase/database.rules.json` - обновлены правила безопасности Firebase

**Статус:** Решено
